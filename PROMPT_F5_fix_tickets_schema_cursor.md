# Prompt cho Cursor — Fix F5: tạo schema bảng `tickets` (backend không boot với ddl-auto=validate)

> Copy toàn bộ phần dưới dán vào Cursor.

---

## NGỮ CẢNH & VẤN ĐỀ

**V-SAT Compass**, backend Spring Boot tại `VSAT/vsat-compass-api/`. Vừa thêm tính năng F5 (ticket báo lỗi) với entity `Ticket` (`@Table(name = "tickets")`).

**Lỗi cần fix:** `application.yml` đặt `spring.jpa.hibernate.ddl-auto: validate` ở profile gốc, **cả dev lẫn prod đều KHÔNG override** (dev chỉ đổi `show-sql`). Repo **không có Flyway/Liquibase/schema.sql**. Với `validate`, Hibernate chỉ kiểm tra schema, **không tạo bảng** → khi khởi động backend với entity `Ticket` mới mà bảng `tickets` chưa tồn tại, app **fail khi boot** (schema validation: thiếu bảng `tickets`). Mockito test PASS vì không load Spring context/DB thật nên không lộ lỗi này.

**Bối cảnh vận hành:** đang demo bằng Postgres local trong Docker container (tên thường là `vsat-pg`, DB `vsat_compass`, user/pass `postgres/postgres` theo dev profile). Neon cloud đang treo; prod để sau.

## HƯỚNG FIX (đã chốt — KHÔNG đổi `ddl-auto`)

Giữ `ddl-auto: validate` (giữ kỷ luật schema, không sửa file `application.yml` đang dirty). Thêm **DDL tường minh** cho bảng `tickets`, áp vào DB local để backend boot lại được, và ghi nợ "chạy DDL này trên prod trước khi deploy F5".

## HẠNG MỤC

1. **Tạo file SQL DDL** trong repo, ví dụ `VSAT/vsat-compass-api/docs/sql/0001_create_tickets.sql`, nội dung idempotent (khớp đúng entity `Ticket`):
   ```sql
   CREATE TABLE IF NOT EXISTS tickets (
       id               BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       question_id      BIGINT,
       reporter_user_id BIGINT      NOT NULL,
       message          TEXT        NOT NULL,
       status           VARCHAR(30) NOT NULL,
       resolver_note    TEXT,
       created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
       updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
   );
   ```
   (Kiểm tra lại tên cột/kiểu so với `entity/Ticket.java`: `id` IDENTITY, `question_id` nullable, `reporter_user_id` NOT NULL, `message` TEXT NOT NULL, `status` VARCHAR(30) NOT NULL — lưu enum `TicketStatus` dạng STRING, `resolver_note` TEXT nullable, `created_at`/`updated_at` TIMESTAMPTZ NOT NULL. Sửa DDL nếu entity khác.)

2. **Áp DDL vào DB local** để backend boot lại được (điều chỉnh tên container/DB nếu khác):
   ```bash
   docker exec -i vsat-pg psql -U postgres -d vsat_compass -f - < VSAT/vsat-compass-api/docs/sql/0001_create_tickets.sql
   ```
   hoặc `\i` trong psql. Xác nhận bảng tồn tại: `\d tickets`.

3. **Verify backend boot + endpoint:** chạy backend profile dev, xác nhận khởi động thành công (không còn lỗi schema validation), `/actuator/health` = UP. Smoke nhanh: `POST /tickets` (token STUDENT) tạo ticket OPEN; `GET /admin/tickets` (token admin) thấy ticket; `PATCH /admin/tickets/{id}` đổi trạng thái OK; student gọi `/admin/tickets` bị chặn.

4. **Ghi nợ vào `PLAN_offline_phase_f.md`** (mục F5 hoặc một mục "Schema debt"): nêu rõ prod (Neon) cũng `validate` nên **phải chạy `0001_create_tickets.sql` trên prod trước khi deploy F5**; cân nhắc chuyển sang Flyway khi lên online.
